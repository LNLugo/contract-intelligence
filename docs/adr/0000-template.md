# ADR-NNNN: Title as a decision, not a topic

- **Status:** Proposed | Accepted | Superseded by ADR-XXXX
- **Date:** YYYY-MM-DD
- **Phase:** N

## Context
What forces are at play: the requirement, the constraint, and what goes wrong if this is decided badly. Two to four sentences.

## Options considered
| Option | Gains | Costs |
|---|---|---|
| A | | |
| B | | |
| C | | |

## Decision
One sentence that starts with "We will" or "I will".

## Consequences
- What becomes easier.
- What becomes harder, or what I now own.
- What risk I accepted knowingly.

## Enterprise vs this build
Where the enterprise version would decide differently and why. Leave blank if they match.

## Evidence
The measurement, test or failure that supports the decision. Link to the build log entry. A Proposed ADR lists the evidence it is waiting for.

## Revisit when
The specific signal that would reopen this decision.

## Interview angle
The 20-second spoken version: the requirement, the decision, the tradeoff, and one number.
